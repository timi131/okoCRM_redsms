# REDSMS для OkoCRM — SMS и коды в Telegram

**SMS клиентам прямо из OkoCRM: из карточки, по шаблону, автодействием в воронке или через ИИ-ассистента.** В ленте сразу видно, дошло ли сообщение. Коды подтверждения сначала уходят в Telegram, где REDSMS берёт плату только за доставленные.

| | |
|---|---|
| ✓ **Статусы в ленте** | Одна галка — отправлено, две — доставлено. Если не доставлено — причина по-русски и кнопка «Повторить» |
| ✓ **Коды через Telegram** | Сначала Telegram, а если у клиента его нет или код не дошёл за 3 минуты — автоматически SMS |
| ✓ **Защита бюджета** | Лимиты в час на аккаунт и на номер, блокировка одинаковых SMS. Ошибка в автодействии не отправит тысячу сообщений |
| ✓ **Без отправок в пустоту** | Закончились деньги или сломался ключ — кнопка SMS выключается, администратор получает письмо |
| ✓ **Отложенная отправка** | До 7 дней вперёд: напоминания о записи, визите, оплате |
| ✓ **Безопасность** | Ключи API зашифрованы, все запросы подписаны, при удалении виджета данные стираются |

**Подключение — три поля:** логин REDSMS, ключ API и имена отправителей.

Тексты для карточки в OkoStore, анонса и FAQ — в [docs/STORE.md](docs/STORE.md).

---

## Для разработчиков

Интеграция состоит из двух частей:

- `widget/` — виджет OkoStore с блоком `sms` в `config.json`. Логики в нём нет: `script.js` пустой, как разрешает документация.
- `okocrm_redsms/` — сервер-мост. Принимает вебхуки OkoCRM, ходит в REDSMS HTTP API и шлёт статусы обратно в OkoCRM. Написан на Python 3.9+. Единственная зависимость — `cryptography` для шифрования секретов, остальное из стандартной библиотеки: sqlite3, http.server, urllib.

## Как это работает

```
OkoCRM ──installed / settings_updated / uninstalled──▶ /okocrm/events ─┐
OkoCRM ──sms.send───────────────────────────────────▶ /okocrm/send    │  мост  ──POST /api/message (dlrUrl)──▶ REDSMS
OkoCRM ◀──PUT senders · POST status · POST events───────────────────────┘        ◀──колбэк /redsms/dlr/{ulid}/{sig}──
```

| Событие | Что делает мост |
|---|---|
| `installed` | Сохраняет `setting_ulid → token` и настройки, отправляет `PUT senders`, проверяет `GET /api/client/info` и шлёт `POST status` (`ok` или `error` с причиной) |
| `settings_updated` | То же, но без нового токена |
| `uninstalled` | Удаляет токен и ключ API, очищает очередь |
| `sms.send` | Проверяет подпись, кладёт сообщение в SQLite и сразу отвечает `{"message_id": "rs-…"}`, укладываясь в лимит 4 с. В фоне делает `POST /api/message` в REDSMS с `dlrUrl` |
| Принято REDSMS | `sms.status: sent` (одна галка) |
| Колбэк REDSMS | `delivered` → две галки; `read`/`reply` → `read`; `reject`, `undelivered`, `timeout`, `no_money`, `bad_number`, `stop_list` и т.д. → `failed` с русским текстом причины |
| Код подтверждения при включённом каскаде | Если в тексте есть «код»/«code»/«пароль» и ровно одно число из 4–8 цифр, мост отправляет `route: tgauth,sms`: сначала код через Telegram Gateway, при недоставке за `TG_VALIDITY` секунд — SMS с полным текстом. Неудача шага Telegram не считается ошибкой, мост переключается на SMS-шаг |
| Колбэк потерян | Через 10 минут мост сам опрашивает `GET /api/message/{uuid}` |
| `401`/`420`/`no_money` | Внеплановая проверка аккаунта. При подтверждённой проблеме — `POST status error`: кнопка SMS гаснет, администратору приходит письмо. Когда проблема устранена — `ok` |

Надёжность:

- **Подпись OkoCRM.** HMAC-SHA256 по сырому телу, сравнение за постоянное время.
- **Колбэки REDSMS.** Свою подпись REDSMS не присылает. Поэтому `dlrUrl` содержит HMAC от `setting_ulid` на `APP_SECRET`, а запросы дополнительно фильтруются по IP REDSMS из их документации.
- **Идемпотентность.** Уникальный ключ `(setting_ulid, message_key)`: повтор `sms.send` возвращает тот же `message_id` и не отправляет SMS второй раз.
- **Нет двойных отправок.** Запрос в REDSMS повторяется только если соединение не установилось. При таймауте сообщение помечается `failed` с просьбой проверить кабинет: у REDSMS нет ключа идемпотентности, и слепой повтор может задвоить SMS. После перезапуска сообщения в состоянии «отправляется» не переотправляются.
- **Outbox для OkoCRM.** Повторы с backoff, `Retry-After` на 429, ожидание на 409/402. Статус уходит не раньше чем через 2 с после ответа на `sms.send`, как требует документация. Для `status` и `senders` хранится только последнее значение.
- **Лимиты.** Ограничения на подключение: в минуту и в час, на один номер в час и на одинаковый текст на тот же номер за 5 минут. Защищают от зацикленного автодействия, которое может отправить тысячи SMS. Превышение даёт менеджеру понятную ошибку в ленте. Сообщения с ошибкой не учитываются, поэтому «Повторить» лимит не съедает.
- **Шифрование.** Ключи API REDSMS и токены OkoCRM хранятся в БД зашифрованными (Fernet). Ключ задаётся в `ENCRYPTION_KEY`, менять его можно без простоя.
- **Без лишних писем.** `POST status` отправляется только при смене состояния: каждое переключение `ok → error` OkoCRM дублирует письмом администратору.

## Настройки виджета у клиента

| Поле | Значение |
|---|---|
| Логин REDSMS | логин кабинета |
| Ключ API REDSMS | cp.redsms.ru → «Настройки → HTTP API» |
| Имена отправителей | через запятую, как зарегистрированы в REDSMS. Допустимо 1–15 символов: латиница, цифры, пробел, `.`, `_`, `-` |
| Коды сначала через Telegram | галочка. Нужен подключённый Telegram Gateway в REDSMS. В Telegram платят только за доставленные коды |
| Лимит SMS в час на аккаунт | пусто — значение по умолчанию (1000), `0` — без лимита |
| Лимит SMS в час на один номер | пусто — значение по умолчанию (10), `0` — без лимита |

Имена приходится вводить вручную: в HTTP API REDSMS нет метода со списком имён отправителей. Если в REDSMS включён белый список IP, в него нужно добавить IP сервера моста.

## Оценка документации

### OkoCRM — https://okocrm.com/api/ — 8/10

Сильные стороны:

- **SMS-раздел написан образцово.** Есть схема подключения, точные таймауты (4 с на `sms.send`, 5 с и 3 попытки на вебхуки), семантика идемпотентности, правила порядка статусов (понижения игнорируются, `delivered` без `sent` заполняет оба), дедупликация в окне 5 с, лимиты (5 rps / 600 rpm с `Retry-After`) и полная таблица кодов ошибок с телами ответов.
- **Чеклист перед публикацией.** Описан путь отладки через личный виджет без модерации.
- **Подпись описана грамотно.** Сказано про сырое тело и `\uXXXX`, про сравнение за постоянное время. Примеры есть на PHP, Node.js и Python.
- **Понятен опыт менеджера.** Указано, какие тексты он видит при таймауте, ошибке и пустом ответе.

Недостатки:

- **Сайт неудобен для чтения.** Вся документация — одна страница примерно на 2 МБ HTML. Нет OpenAPI или Postman-коллекции и якорных ссылок на разделы. Упомянутая «Интеграция SMS-шлюза с OkoCRM» вынесена на отдельную страницу, и при проверке она не открылась (таймаут).
- **Не задокументированы типы `settings.fields`.** В примере только `text`, поля-пароля для ключа API нет. Поэтому ключ REDSMS виден в настройках открытым текстом.
- **Неясно, как ведёт себя OkoCRM с длинными SMS.** Сказано только «деление на части — на вашей стороне».
- **Нет тестовой песочницы.** Отлаживаться можно только на живом аккаунте через личный виджет.
- **Не описан общий REST API v2.** Неясно, откуда берётся Bearer-токен и какие у него лимиты. Для этой интеграции он не нужен.
- **Не сказано, с каких IP приходят вебхуки OkoCRM.** Остаётся только проверка подписи (впрочем, её достаточно).

### REDSMS — https://docs.redsms.ru/http/ — 6/10

Сильные стороны:

- **Хорошо структурирована.** Docusaurus, отдельный справочник и описание объекта сообщения с полным списком статусов и пометкой конечных.
- **Понятны авторизация и ограничения.** Авторизация — `md5(ts + key)`; описаны технические и настраиваемые лимиты и коды `400`/`401`/`420`.

Недостатки:

- **Webhook описан скупо.** Нет списка полей, которые реально приходят. Неясно, совпадает ли формат для `dlrUrl` из запроса с общим колбэком из кабинета. Ничего не сказано о политике повторов, и нет подписи — только «принимайте с этих IP».
- **Нет идемпотентности при отправке.** Ни ключа, ни `clientField` во входных параметрах (`clientField` есть в объекте сообщения, но как его передать — не описано). Повтор после таймаута рискует задвоить SMS.
- **Нет методов для имён отправителей и входящих SMS.** Поэтому интеграция не умеет присылать в OkoCRM `sms.incoming`, а имена отправителей вводятся вручную.
- **Не описан формат ошибок.** Тексты ошибок в `errors[].message` только на английском, и их список не задокументирован.
- **Устаревший пример на Python.** В нём `unicode(time.time())` — это Python 2.
- **Неточность в справочнике.** У `textDelimeter` описание «разделитель номеров телефонов», хотя по смыслу это разделитель текстов.

## Что не поддерживается и почему

- **Входящие SMS (`sms.incoming`).** В HTTP API REDSMS нет приёма ответных SMS.
- **Уведомления через Telegram.** Telegram Gateway REDSMS принимает только коды из 4–8 цифр, поэтому «Ваш заказ готов» уходит обычной SMS.
- **Каналы Viber и VK.** Не работают и не планируются. Из каналов REDSMS интеграция использует только SMS и Telegram Gateway для кодов.

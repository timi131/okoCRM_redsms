# REDSMS для OkoCRM — SMS со статусами доставки

**SMS клиентам прямо из OkoCRM: из карточки, по шаблону, автодействием в воронке или через ИИ-ассистента.** В ленте сразу видно, дошло ли сообщение. Для переписки с клиентами в Telegram используйте штатную интеграцию мессенджеров OkoCRM — плагин отвечает за SMS.

| | |
|---|---|
| ✓ **Статусы в ленте** | Одна галка — отправлено, две — доставлено. Если не доставлено — причина по-русски и кнопка «Повторить» |
| ✓ **Защита бюджета** | Лимиты в час на аккаунт и на номер — по желанию клиента, блокировка одинаковых SMS. Ошибка в автодействии не отправит тысячу сообщений |
| ✓ **Без отправок в пустоту** | Закончились деньги или сломался ключ — кнопка SMS выключается, администратор получает письмо |
| ✓ **Отложенная отправка** | До 7 дней вперёд: напоминания о записи, визите, оплате |
| ✓ **Безопасность** | Ключи API зашифрованы, все запросы подписаны, при удалении виджета данные стираются |

**Подключение — три поля:** логин REDSMS, ключ API и имена отправителей.

**Поддержка:** [help@redsms.ru](mailto:help@redsms.ru)

Тексты для карточки в OkoStore, анонса и FAQ — в [docs/STORE.md](docs/STORE.md).

## Для разработчиков

Интеграция состоит из двух частей:

- `widget/` — виджет OkoStore с блоком `sms` в `config.json`. Логики в нём нет: `script.js` пустой, как разрешает документация.
- `okocrm_redsms/` — сервер-мост. Принимает вебхуки OkoCRM, ходит в REDSMS HTTP API и шлёт статусы обратно в OkoCRM. Написан на Python 3.9+. Единственная зависимость — `cryptography` для шифрования секретов, остальное из стандартной библиотеки: sqlite3, http.server, urllib.

## Как это работает

```
OkoCRM ──installed / settings_updated / uninstalled──▶ /okocrm/events ─┐
OkoCRM ──sms.send───────────────────────────────────▶ /okocrm/send    │  мост  ──POST /api/message (dlrUrl)──▶ REDSMS
OkoCRM ◀──PUT senders · POST status · POST events───────────────────────┘        ◀──колбэк /redsms/dlr/{ulid}/{sig}──
```

| Событие | Что делает мост |
|---|---|
| `installed` | Сохраняет `setting_ulid → token` и настройки, отправляет `PUT senders`, проверяет `GET /api/client/info` и шлёт `POST status` (`ok` или `error` с причиной) |
| `settings_updated` | То же, но без нового токена |
| `uninstalled` | Удаляет токен и ключ API, очищает очередь |
| `sms.send` | Проверяет подпись, кладёт сообщение в SQLite и сразу отвечает `{"message_id": "rs-…"}`, укладываясь в лимит 4 с. В фоне делает `POST /api/message` в REDSMS с `dlrUrl` |
| Принято REDSMS | `sms.status: sent` (одна галка) |
| Колбэк REDSMS | `delivered` → две галки; `read`/`reply` → `read`; `reject`, `undelivered`, `timeout`, `no_money`, `bad_number`, `stop_list` и т.д. → `failed` с русским текстом причины |
| Код подтверждения (каскад выключен) | Заготовка на будущее, сейчас выключена флагом `ENABLE_TELEGRAM_CASCADE=false` и полем в виджете. Если включить: текст со словом «код»/«code»/«пароль» и одним числом из 4–8 цифр уходит `route: tgauth,sms` — сначала код через Telegram Gateway, при недоставке за `TG_VALIDITY` секунд SMS с полным текстом |
| Колбэк потерян | Через 10 минут мост сам опрашивает `GET /api/message/{uuid}` |
| `401`/`420`/`no_money` | Внеплановая проверка аккаунта. При подтверждённой проблеме — `POST status error`: кнопка SMS гаснет, администратору приходит письмо. Когда проблема устранена — `ok` |

Надёжность:

- **Подпись OkoCRM.** HMAC-SHA256 по сырому телу, сравнение за постоянное время.
- **Колбэки REDSMS.** Свою подпись REDSMS не присылает. Поэтому `dlrUrl` содержит HMAC от `setting_ulid` на `APP_SECRET`, а запросы дополнительно фильтруются по IP REDSMS из их документации.
- **Идемпотентность.** Уникальный ключ `(setting_ulid, message_key)`: повтор `sms.send` возвращает тот же `message_id` и не отправляет SMS второй раз.
- **Нет двойных отправок.** Запрос в REDSMS повторяется только если соединение не установилось. При таймауте сообщение помечается `failed` с просьбой проверить кабинет: у REDSMS нет ключа идемпотентности, и слепой повтор может задвоить SMS. После перезапуска сообщения в состоянии «отправляется» не переотправляются.
- **Outbox для OkoCRM.** Повторы с backoff, `Retry-After` на 429, ожидание на 409/402. Статус уходит не раньше чем через 2 с после ответа на `sms.send`, как требует документация. Для `status` и `senders` хранится только последнее значение.
- **Лимиты.** По умолчанию лимитов объёма нет: клиент сам задаёт в настройках виджета лимит в час на аккаунт и на один номер. Всегда действует только защита от дублей — одинаковый текст на тот же номер за 5 минут. Защищают от зацикленного автодействия, которое может отправить тысячи SMS. Превышение даёт менеджеру понятную ошибку в ленте. Сообщения с ошибкой не учитываются, поэтому «Повторить» лимит не съедает.
- **Шифрование и персональные данные.** Ключи API REDSMS, токены OkoCRM и номера телефонов хранятся в БД зашифрованными (Fernet). Текст SMS стирается сразу после передачи в REDSMS, поэтому коды подтверждения не хранятся. В логах номера маскируются. Подробнее — в [SECURITY.md](SECURITY.md).
- **Без лишних писем.** `POST status` отправляется только при смене состояния: каждое переключение `ok → error` OkoCRM дублирует письмом администратору.

## Настройки виджета у клиента

| Поле | Значение |
|---|---|
| Логин REDSMS | логин кабинета |
| Ключ API REDSMS | cp.redsms.ru → «Настройки → HTTP API» |
| Имена отправителей | через запятую, как зарегистрированы в REDSMS. Допустимо 1–15 символов: латиница, цифры, пробел, `.`, `_`, `-` |
| Лимит SMS в час на аккаунт | необязательно; пусто — без лимита |
| Лимит SMS в час на один номер | необязательно; пусто — без лимита |

Имена приходится вводить вручную: в HTTP API REDSMS нет метода со списком имён отправителей. Если в REDSMS включён белый список IP, в него нужно добавить IP сервера моста.

Быстрый старт:

```bash
python3 -W ignore -m unittest discover -s tests -v   # тесты
cp .env.example .env && docker build -t okocrm-redsms .
docker run -d --env-file .env --read-only --tmpfs /tmp --cap-drop ALL --security-opt no-new-privileges \
  -p 127.0.0.1:8080:8080 -v okocrm-redsms:/data okocrm-redsms
tools/build_widget.sh                                  # архив виджета для OkoStore
```

## Что не поддерживается и почему

- **Входящие SMS (`sms.incoming`).** В HTTP API REDSMS нет приёма ответных SMS.
- **Telegram.** Для переписки и уведомлений в Telegram у OkoCRM есть штатная интеграция мессенджеров. Каскад «код в Telegram → SMS» через Telegram Gateway REDSMS реализован в бэкенде, но выключен (`ENABLE_TELEGRAM_CASCADE`) и в виджете не показывается: Telegram Gateway принимает только коды из 4–8 цифр.
- **Каналы Viber и VK.** Не работают и не планируются.

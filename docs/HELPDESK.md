# Руководство техподдержки REDSMS: диагностика виджета OkoCRM

Как разбирать обращения клиентов, которые отправляют SMS из OkoCRM через виджет REDSMS: что спросить у клиента, где смотреть, что означает каждая ошибка и когда эскалировать.

- **Первая линия (L1)** работает в кабинете REDSMS и по этому руководству. Доступ к серверу интеграции не нужен.
- **Вторая линия (L2)** дополнительно запускает на сервере интеграции команду диагностики и читает логи (раздел «Инструменты L2»).

Контакт поддержки для клиентов: **help@redsms.ru**.

---

## 1. Как устроена интеграция — за минуту

```
OkoCRM (менеджер, шаблон, автодействие)
   │  «отправить SMS»                                  ▲ статусы: одна галка / две / красная заметка
   ▼                                                   │
Интеграция (сервис-мост REDSMS ↔ OkoCRM) ──────────────┘
   │  отправка по HTTP API REDSMS c логином и ключом клиента
   ▼
REDSMS → оператор → абонент
   │  статус доставки (колбэк) возвращается в интеграцию, она передаёт его в OkoCRM
```

Важно для диагностики:

- **Интеграция отправляет SMS от имени клиента** — его логином и ключом API. Каждое SMS из OkoCRM видно в кабинете REDSMS клиента как обычное сообщение через HTTP API.
- **Интеграция отвечает OkoCRM сразу**, а в REDSMS отправляет через доли секунды. Поэтому ошибки бывают двух видов: **сразу при отправке** (текст в окне OkoCRM) и **после отправки** (красная заметка в ленте с кнопкой «Повторить»).
- **Подключение = один аккаунт OkoCRM.** Его идентифицирует поддомен (`<поддомен>.okocrm.com`) и `setting_ulid`.
- **Номера в базе интеграции зашифрованы, текст SMS стирается** сразу после передачи в REDSMS. Номер и текст сообщения смотрите в кабинете REDSMS, а не в интеграции.

## 2. Что запросить у клиента

Попросите сразу всё, что есть, — это экономит переписку:

- [ ] **Поддомен OkoCRM** — из адреса CRM: `https://<поддомен>.okocrm.com`
- [ ] **Логин REDSMS**
- [ ] **Скриншот ошибки** — из ленты клиента или из настроек виджета (вкладка «Подключение»)
- [ ] **Время отправки** (с часовым поясом) и **последние 4 цифры номера**
- [ ] **Как отправляли:** из карточки, по шаблону, автодействием в воронке, через ИИ-ассистента
- [ ] Это **одно сообщение** или **все** перестали уходить

> [!WARNING]
> Никогда не просите у клиента ключ API, пароль или «Секретный ключ» виджета — ни в тикете, ни в чате. Для диагностики они не нужны. Если клиент прислал ключ сам — попросите перевыпустить его в «Настройки → HTTP API» и пересохранить в настройках виджета.

## 3. Быстрая диагностика: с чего начать

1. **Найдите сообщение в кабинете REDSMS** клиента по времени и номеру.
   - **Сообщения нет** → проблема **до REDSMS**: настройки виджета, лимиты интеграции, интеграция недоступна. → разделы 4 и 5.
   - **Сообщение есть** → смотрите его **статус в REDSMS**. → раздел 6. Если в REDSMS статус есть, а в OkoCRM нет — раздел 7.
2. **Все SMS перестали уходить сразу у клиента** → почти всегда настройки или баланс: раздел 4.
3. **Перестали уходить у всех клиентов** → интеграция недоступна: эскалация DevOps (раздел 10).

## 4. Ошибки в настройках виджета (вкладка «Подключение»)

Эти тексты клиент видит в настройках виджета. Пока ошибка висит, **кнопка SMS в карточке неактивна**, SMS из автодействий получают в ленте этот же текст, а администратор аккаунта OkoCRM получает письмо. Интеграция перепроверяет ключ и баланс **раз в 10 минут** и снимает ошибку сама; чтобы проверить сразу, клиент пересохраняет настройки виджета.

| Текст ошибки | Причина | Что проверить в кабинете REDSMS | Что ответить клиенту |
|---|---|---|---|
| «REDSMS отклонил авторизацию: проверьте логин и ключ API, а также белый список IP в настройках HTTP API REDSMS» | Неверный логин или ключ; ключ перевыпущен; IP интеграции не в белом списке | Логин клиента; включён ли белый список IP в «Настройки → HTTP API» | Проверить логин, создать ключ заново и вставить в настройки виджета; добавить IP интеграции в белый список (уточнить IP у L2) |
| «Аккаунт REDSMS не активирован: нужен подтверждённый договор» | Нет подписанного договора | Статус договора | Подписать договор |
| «Закончился баланс в кабинете REDSMS» | Баланс + овердрафт ≤ 0 | Баланс, овердрафт | Пополнить баланс; отправка включится сама в течение 10 минут |
| «Укажите хотя бы одно имя отправителя, зарегистрированное в REDSMS… Не подошли: …» | Имена не введены или не прошли проверку: кириллица, длиннее 15 символов, недопустимые символы | Зарегистрированные имена отправителя | Ввести имена латиницей, точно как в REDSMS, через запятую |
| «Укажите логин и ключ API REDSMS в настройках виджета» | Поле пустое | — | Заполнить логин и ключ |
| Ошибки нет, но **имена отправителей не появились** | Интеграция не получила событие установки или не смогла передать имена в OkoCRM | — | Пересохранить настройки виджета. Не помогло — L2 (раздел 8: «Статус в OkoCRM: ещё не отправлялся», «Очередь в OkoCRM») |

## 5. Ошибка сразу при отправке

Сообщение до REDSMS **не дошло** — в кабинете его нет. Текст клиент видит в окне отправки или в ленте.

| Текст | Причина | Что делать |
|---|---|---|
| «Лимит интеграции REDSMS: не больше N SMS в минуту / в час / в час на один номер» | Сработала защита от зацикленных автодействий | Если это легальная рассылка — поднять лимиты в настройках виджета («Лимит SMS в час…», `0` — без лимита). Если автодействие зациклилось — исправить воронку. Лимит в минуту (60) меняет только L2/DevOps |
| «Лимит интеграции REDSMS: такое же SMS на этот номер уже отправлено за последние 5 мин» | Одинаковый текст на тот же номер повторно | Обычно двойное срабатывание автодействия. «Повторить» после ошибки лимит не съедает |
| «Некорректный номер получателя: …» | В номере меньше 10 или больше 15 цифр | Исправить номер в карточке контакта |
| «Пустой текст SMS» | Шаблон без текста или подстановки дали пустоту | Проверить шаблон |
| «REDSMS принимает отложенную отправку не более чем на 7 дней вперёд» | Время отправки дальше 7 дней | Ограничение REDSMS: выбрать более близкую дату |
| «Подключение REDSMS не найдено: пересохраните настройки виджета» | Интеграция не знает это подключение (не дошло событие установки) | Пересохранить настройки виджета; не помогло — L2 |
| «У SMS-шлюза нет ни одного имени отправителя» *(текст OkoCRM)* | В OkoCRM не попал список имён | См. раздел 4, последняя строка |
| «SMS-шлюз не отвечает, попробуйте позже» *(текст OkoCRM)* | Интеграция недоступна или не ответила за 4 секунды | Проверить вкладку «Подключение» (если там ошибка — раздел 4). Ошибки нет — L2/DevOps: проверить доступность интеграции |
| «SMS-шлюз отклонил сообщение без объяснения причины» *(текст OkoCRM)* | Неожиданная ошибка | L2: логи по времени отправки |

## 6. Сообщение дошло до REDSMS, но не доставлено (красная заметка)

Красная заметка в ленте содержит причину. Большинство — это **статусы REDSMS**, их можно проверить в кабинете по `uuid` сообщения.

| Текст в ленте | Статус REDSMS | Что делать |
|---|---|---|
| «Сообщение отклонено модератором REDSMS» | `reject` | Проверить текст и имя отправителя по правилам модерации |
| «Сообщение не доставлено абоненту» | `undelivered` | Абонент недоступен / номер не обслуживается. Повторить позже |
| «Оператор не подтвердил доставку за отведённое время» | `timeout` | Статус от оператора не пришёл за 24 часа |
| «Недостаточно средств на балансе REDSMS» | `no_money` или ответ 420 | Пополнить баланс |
| «REDSMS отклонил сообщение как дубликат (лимит на дубликаты в настройках REDSMS)» | `doubled` | Настройка «Лимит на дубликаты» в кабинете клиента («Настройки → Ограничения») |
| «Превышен лимит отправки, заданный в настройках REDSMS» | `limit_exceeded` | Лимиты в кабинете клиента («Настройки → Ограничения») |
| «Некорректный номер телефона получателя» | `bad_number` | Исправить номер |
| «Номер получателя находится в стоп-листе REDSMS» | `stop_list` | Номер в стоп-листе |
| «Направление закрыто для отправки в настройках REDSMS» | `route_closed` | Ограничения по странам или закрытое направление в кабинете клиента. **Встречалось у пилотного клиента** — после открытия направления SMS дошла |
| «Неизвестная ошибка REDSMS» | `error` | Разбор по `uuid` на стороне REDSMS |
| «REDSMS отклонил сообщение: <причина>» | ответ 400 при создании | Причина из ответа REDSMS (лимиты, дубликаты, номер) — сообщения в кабинете может не быть |
| «REDSMS отклонил авторизацию: проверьте логин и ключ API» | ответ 401 | См. раздел 4, первая строка |
| «REDSMS недоступен, сообщение не отправлено. Повторите позже» | соединение не установилось | Сообщение точно **не** отправлено, «Повторить» безопасно. Массово — эскалация |
| «REDSMS не ответил вовремя. Проверьте сообщение в кабинете REDSMS, прежде чем повторять отправку» | таймаут после отправки запроса | **Сначала найти сообщение в кабинете.** Есть — не повторять (будет дубль). Нет — повторить |
| «Отправка прервана перезапуском интеграции. Проверьте сообщение в кабинете REDSMS, прежде чем повторять» | интеграцию перезапустили в момент отправки | Как строкой выше |

## 7. Статусы не обновляются

| Симптом | Причина | Что делать |
|---|---|---|
| Одна галка долго, в кабинете REDSMS — «доставлено» | Колбэк статуса от REDSMS не дошёл до интеграции | Интеграция сама запрашивает статус в REDSMS через **10 минут** — подождать. Если не обновилось за 30 минут — L2: «Очередь в OkoCRM» и логи |
| Одна галка долго, в кабинете тоже «в процессе» | Ждём оператора | Нормально: статус от оператора может идти до 24 часов |
| Ни одной галки, в кабинете сообщение есть | Интеграция не смогла передать статус в OkoCRM (тариф OkoCRM не оплачен, OkoCRM недоступен, лимит запросов) | L2: «Очередь в OkoCRM» покажет ошибку от OkoCRM. HTTP 402 = у клиента не оплачен тариф OkoCRM |
| Нет сообщения ни в ленте, ни в кабинете | OkoCRM не вызвал интеграцию | Проверить, что виджет установлен и настройки сохранены. Ошибка в окне отправки — раздел 5 |

## 8. Инструменты L2: команда диагностики

Запускается на сервере интеграции, **только читает** данные, ключи и токены не выводит, номера маскирует (`+7999***4567`). Доступ к серверу выдают DevOps.

```bash
cd <каталог развёртывания интеграции>
sudo docker compose exec bridge python -m okocrm_redsms diag --subdomain <поддомен>
```

| Команда | Что показывает |
|---|---|
| `diag --subdomain <поддомен>` | Подключение клиента, сводка ошибок за сутки, очередь в OkoCRM, последние 20 сообщений |
| `diag --subdomain <поддомен> --check` | То же + **проверка прямо сейчас**: логин, ключ, договор и баланс в REDSMS |
| `diag --message rs-…` | Одно сообщение по `message_id` (так его знает OkoCRM) |
| `diag --uuid <uuid>` | Одно сообщение по `uuid` из кабинета REDSMS |
| `diag --list` | Все подключения: поддомен, статус, удалено ли |
| `--limit 50` | Показать больше сообщений |

Как читать вывод:

| Строка | Что значит |
|---|---|
| `УДАЛЕНО клиентом` | Клиент удалил виджет. Чтобы заработало — установить заново |
| `Токен OkoCRM: НЕТ` | Подключение без токена — клиенту пересохранить настройки или перевыпустить токен во вкладке «Подключение» |
| `Отклонены проверкой: …` | Эти имена отправителей не приняты — раздел 4 |
| `Статус в OkoCRM: error — …` | Текст ошибки, который сейчас видит клиент (раздел 4) |
| `Статус в OkoCRM: ещё не отправлялся` | Проверка подключения ещё не завершилась или REDSMS API был недоступен — запустить с `--check` |
| `Не доставлено за сутки: N × статус` | Чего больше всего среди недоставленных — сразу видно, куда смотреть (раздел 6) |
| `Очередь в OkoCRM: N … ошибка: HTTP 402` | У клиента не оплачен тариф OkoCRM — OkoCRM не принимает статусы |
| `… ошибка: HTTP 429` | Лимит запросов OkoCRM — разгрузится сам |
| `… ошибка: HTTP 404/401` | Токен подключения недействителен — клиенту пересохранить настройки или перевыпустить токен |
| `состояние queued / sending` дольше минуты | Сообщение застряло до REDSMS — эскалация |
| `uuid в кабинете REDSMS: —` | До REDSMS сообщение не дошло (ошибка разделов 5–6) |
| `Проверка REDSMS сейчас: REDSMS API не ответил` | Нет связи интеграции с REDSMS — эскалация DevOps |

## 9. Инструменты L2: логи

```bash
sudo docker compose logs --since 2h bridge | grep <setting_ulid или rs-… или uuid>
```

| Строка в логе | Что значит |
|---|---|
| `installed: <ulid> (<поддомен>)` | Клиент установил виджет / сохранил настройки впервые |
| `settings_updated: <ulid>` | Клиент изменил настройки |
| `uninstalled: <ulid>` | Клиент удалил виджет |
| `status <ulid> → ok / error <текст>` | Изменилось состояние подключения (раздел 4) |
| `submitted rs-… → REDSMS <uuid> (sms, created)` | Сообщение принято REDSMS |
| `REDSMS send rs-…: HTTP 400 …` | REDSMS отклонил сообщение, причина в ответе (номера замаскированы) |
| `REDSMS send rs-…: ConnectionRefused/Timeout` | Нет связи с REDSMS |
| `лимит <ulid>: …` | Сработал лимит интеграции |
| `неверная подпись запроса …` | Запрос не от OkoCRM или неверный ключ виджета на сервере — эскалация DevOps |
| `устаревший запрос …` | Запрос старше 15 минут — проверить время на сервере (NTP) |
| `OkoCRM POST /events → HTTP …` | OkoCRM не принял статус |
| `DLR с чужого IP …` | Колбэк статуса пришёл не с адресов REDSMS — проверить список IP колбэков |

## 10. Когда и куда эскалировать

| Ситуация | Кому |
|---|---|
| Не отправляется у **всех** клиентов; «SMS-шлюз не отвечает» массово; `https://<домен интеграции>/healthz` не отвечает | **DevOps** — срочно |
| Сертификат домена интеграции истёк или скоро истечёт | **DevOps** — срочно (без сертификата OkoCRM не отправит ни одного SMS) |
| `Проверка REDSMS сейчас: REDSMS API не ответил`, массовые «REDSMS недоступен» | **DevOps** + команда REDSMS API |
| Много `неверная подпись запроса` | **DevOps**: проверить ключ виджета на сервере |
| Сообщения висят в `queued`/`sending`, «Внутренняя ошибка интеграции REDSMS», непонятные ошибки | **Разработчики интеграции** |
| Ошибка на стороне OkoCRM (окно отправки не открывается, виджет не ставится) | **Поддержка OkoCRM**: support@okocrm.com, 8 800 777 54 91 |

Шаблон эскалации:

```
Клиент: <поддомен OkoCRM>, логин REDSMS <логин>
Симптом: <текст ошибки / что не работает>, с <время, МСК>
Масштаб: один клиент / несколько / все
Сообщение: message_id rs-… / uuid REDSMS …
Что уже проверено: <кабинет REDSMS, diag --check, логи>
```

## 11. Чего не делать

- Не просить и не пересылать ключ API, пароль, «Секретный ключ» виджета, токены.
- Не нажимать «Повторить» (и не советовать клиенту) при ошибках «REDSMS не ответил вовремя» и «Отправка прервана перезапуском», пока не проверено, что сообщения нет в кабинете REDSMS: иначе абонент получит дубль.
- Не править базу интеграции вручную — только команда `diag` (чтение).
- Не перезапускать интеграцию без DevOps: в момент перезапуска отправки на несколько секунд недоступны.

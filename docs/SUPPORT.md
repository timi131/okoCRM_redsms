# Поддержка и эксплуатация

## Где смотреть

```bash
docker logs -f okocrm-redsms          # события: installed, submitted, status, ошибки REDSMS/OkoCRM
curl https://sms.example.com/healthz  # жив ли мост и доступна ли база (503, если нет)
```

Токены и ключи API в лог не пишутся. Чтобы видеть каждый HTTP-запрос, задайте `LOG_LEVEL=DEBUG`.

Состояние хранится в SQLite (`/data/okocrm_redsms.sqlite3` в контейнере):

```bash
docker exec -it okocrm-redsms python - <<'EOF'
import sqlite3; c = sqlite3.connect('/data/okocrm_redsms.sqlite3')
print(c.execute("select setting_ulid, subdomain, status, status_message from connections where deleted_at is null").fetchall())
print(c.execute("select id, phone, state, redsms_status, oko_status from messages order by created_at desc limit 20").fetchall())
print(c.execute("select kind, attempts, last_error from outbox").fetchall())
EOF
```

Как найти клиента: `subdomain` — это поддомен его аккаунта OkoCRM. Сообщение можно найти по `message_id` (`rs-…`), который OkoCRM хранит у себя, или по `redsms_uuid` из кабинета REDSMS.

## Частые проблемы

| Что видит клиент | Причина | Что делать |
|---|---|---|
| «REDSMS отклонил авторизацию…» в настройках виджета | Неверный логин или ключ, либо IP моста не в белом списке REDSMS | Проверить логин и ключ. Добавить IP сервера моста в cp.redsms.ru → «Настройки → HTTP API» |
| «Закончился баланс в кабинете REDSMS» | Нулевой баланс | Пополнить баланс. Мост сам снимет ошибку при следующей проверке (раз в 10 мин) или при пересохранении настроек |
| «Аккаунт REDSMS не активирован» | Нет подтверждённого договора | Подписать договор в REDSMS |
| «Укажите хотя бы одно имя отправителя… Не подошли: …» | Поле пустое, или имена не прошли проверку (кириллица, длиннее 15 символов). Отклонённые имена перечислены в тексте ошибки и в логе | Ввести имена латиницей, как в REDSMS |
| «У SMS-шлюза нет ни одного имени отправителя» | Мост не смог отправить `PUT senders` | Проверить логи и `outbox`, пересохранить настройки виджета |
| «SMS-шлюз не отвечает, попробуйте позже» | Мост недоступен или не ответил за 4 с | Проверить `healthz`, TLS, нагрузку на сервер |
| «Подключение REDSMS не найдено…» | До моста не дошёл `installed`, например мост был выключен или потерял БД | Клиенту — пересохранить настройки виджета или перевыпустить токен |
| «REDSMS отклонил сообщение: …» | REDSMS вернул 400: лимит дубликатов, общий лимит, некорректный номер | Посмотреть текст ошибки и настройки ограничений в кабинете REDSMS |
| «REDSMS не ответил вовремя…» / «Отправка прервана перезапуском…» | Результат неизвестен | Найти сообщение в кабинете REDSMS. Нажимать «Повторить», только если его там нет |
| Висит одна галка | Колбэк не дошёл | Мост через 10 минут сам опросит REDSMS. Если статус так и не пришёл — проверить `TRUST_X_FORWARDED_FOR` и `REDSMS_ALLOWED_IPS` (403 на `/redsms/dlr/` в логах) |
| «Недостаточно средств на балансе REDSMS» в ленте | Статус `no_money` или ответ 420 | Пополнить баланс |
| «Лимит интеграции REDSMS: …» | Сработал лимит: в минуту, в час, на номер или на одинаковый текст | Если это зацикленное автодействие — исправить его. Если это легальная рассылка — поднять лимиты в настройках виджета (часовые) или в `.env` (минутный и окно дублей) |
| С каскадом коды всё равно уходят SMS | Telegram Gateway не подключён в REDSMS, у абонента нет Telegram, или в тексте нет слова «код»/одного числа 4–8 цифр | Проверить текст шаблона и подключение Telegram Gateway в REDSMS. В логе маршрут виден в строке `submitted` |
| «Telegram не доставил код, а SMS-шаг каскада REDSMS не запустился» | REDSMS не создал SMS-шаг за 30 минут | Проверить сообщение в кабинете REDSMS, обратиться в их поддержку |

## Регламентные операции

**Обновление моста.** `git pull`, затем `docker build` и пересоздание контейнера (команда в [CONNECT.md](CONNECT.md)). База лежит в томе `okocrm-redsms` и при обновлении не теряется. После перезапуска сообщения в очереди отправляются, а прерванные на середине помечаются ошибкой, чтобы не отправить SMS дважды.

**Хранение данных.** Завершённые сообщения и удалённые подключения старше `RETENTION_DAYS` (по умолчанию 30 дней) удаляются автоматически раз в час. `0` — хранить всегда.

**Резервная копия.** Копируйте файл БД из тома, например раз в сутки. Без БД мост не знает токены клиентов. Тогда каждому клиенту придётся пересохранить настройки или перевыпустить токен.

```bash
docker exec okocrm-redsms python -c "import sqlite3; s=sqlite3.connect('/data/okocrm_redsms.sqlite3'); s.backup(sqlite3.connect('/data/backup.sqlite3'))"
docker cp okocrm-redsms:/data/backup.sqlite3 ./backup-$(date +%F).sqlite3
```

**Сброс секретного ключа виджета** (OkoStore → «Мои виджеты»). Старый ключ сразу перестаёт работать у всех клиентов. Новый нужно немедленно вписать в `OKOCRM_WIDGET_PRIVATE_KEY` и перезапустить мост. Пока этого не сделали, все запросы OkoCRM получают 403.

**`APP_SECRET`.** Не меняйте. Колбэки REDSMS по уже отправленным сообщениям перестанут приниматься. Статусы всё равно подтянутся опросом, но с задержкой.

**Ключ шифрования (`ENCRYPTION_KEY`).** Ключи API REDSMS и токены OkoCRM хранятся в БД зашифрованными. Смена ключа без простоя:
1. Сгенерировать новый: `python3 -m okocrm_redsms genkey`.
2. Задать `ENCRYPTION_KEY=новый,старый` и перезапустить: при старте все секреты перешифруются новым ключом.
3. Оставить `ENCRYPTION_KEY=новый` и перезапустить ещё раз.

С неверным ключом сервис не стартует и пишет, что ключ не совпадает. Данные при этом не портятся. Если ключ потерян, удалите БД (или строки `connections`) и попросите клиентов пересохранить настройки виджета.

**Новая версия виджета.** Поднимите `version` в `widget/config.json`, соберите архив `tools/build_widget.sh` и загрузите новую версию. Если меняются `sms.webhook_url` или `sms.send_url`, старый адрес должен работать, пока новая версия не пройдёт модерацию.

## Безопасность

- Ключи API REDSMS и токены OkoCRM в БД зашифрованы (Fernet: AES-128 + HMAC). Ключ шифрования храните отдельно от резервных копий БД.
- Запросы OkoCRM без верной подписи HMAC-SHA256 отклоняются.
- Колбэки REDSMS принимаются только по подписанному URL и только с IP REDSMS.
- При удалении виджета токен и ключ API клиента стираются из БД.

# Подключение

Как развернуть мост, собрать виджет и подключить его в OkoCRM. Порядок важен: сначала сервер, потом виджет.

## Что понадобится

- Сервер с публичным IP и доменом, например `sms.example.com`. Подойдёт VPS с 1 vCPU и 512 МБ RAM.
- Docker (или Python 3.9+) и TLS-сертификат. Проще всего поставить Caddy: он получает сертификат сам.
- Аккаунт OkoCRM с доступом к OkoStore → «Мои виджеты».
- Для проверки — аккаунт REDSMS с подтверждённым договором, ключом API и зарегистрированным именем отправителя.

## 1. Развернуть мост

```bash
git clone <URL репозитория> okocrm-redsms && cd okocrm-redsms
cp .env.example .env
```

Заполнить `.env`:

| Переменная | Значение |
|---|---|
| `OKOCRM_WIDGET_PRIVATE_KEY` | Секретный ключ виджета. Пока его нет, впишите временное значение и замените на шаге 3 |
| `APP_SECRET` | Длинная случайная строка, например `openssl rand -hex 32`. **Не меняйте после запуска**: на ней подписаны адреса колбэков у отправленных сообщений |
| `PUBLIC_BASE_URL` | `https://sms.example.com` |
| `TRUST_X_FORWARDED_FOR` | `true`, если перед мостом стоит Caddy или nginx (обычно да) |

Запустить:

```bash
docker build -t okocrm-redsms .
docker run -d --name okocrm-redsms --restart unless-stopped --env-file .env \
  -p 127.0.0.1:8080:8080 -v okocrm-redsms:/data okocrm-redsms
```

Настроить TLS. Пример `Caddyfile`:

```
sms.example.com {
    reverse_proxy 127.0.0.1:8080
}
```

Проверить:

```bash
curl https://sms.example.com/healthz
# {"ok": true}
```

## 2. Собрать виджет

1. В [widget/config.json](../widget/config.json) заменить `sms.example.com` в `sms.webhook_url` и `sms.send_url` на свой домен.
2. Заменить `author` на своё имя или название компании.
3. Положить в `widget/` файл `logo.png` — иконку виджета, квадрат около 256×256.
4. Собрать архив:

   ```bash
   tools/build_widget.sh
   # → dist/redsms-widget-<версия>.zip
   ```

При каждой новой загрузке поднимайте `version` в `config.json` (semver).

## 3. Загрузить виджет в OkoCRM как личный

1. OkoCRM → OkoStore → «Мои виджеты» → загрузить архив. Выберите **личный** виджет: он ставится только в ваш аккаунт и не проходит модерацию.
2. На странице виджета скопировать «Секретный ключ». Вписать его в `.env` как `OKOCRM_WIDGET_PRIVATE_KEY` и пересоздать контейнер:

   ```bash
   docker rm -f okocrm-redsms && docker run -d --name okocrm-redsms --restart unless-stopped \
     --env-file .env -p 127.0.0.1:8080:8080 -v okocrm-redsms:/data okocrm-redsms
   ```

3. Установить виджет в своём аккаунте и заполнить настройки:

   | Поле | Что ввести |
   |---|---|
   | Логин REDSMS | логин кабинета cp.redsms.ru |
   | Ключ API REDSMS | cp.redsms.ru → «Настройки → HTTP API» |
   | Имена отправителей | через запятую, точно как в REDSMS: 1–15 символов, латиница, цифры, пробел, `.`, `_`, `-` |

4. Сохранить. В логах моста (`docker logs -f okocrm-redsms`) должны появиться `installed` и `status … → ok`. Во вкладке «Подключение» виджета видны имена отправителей.

Если в REDSMS включён белый список IP, добавьте в него IP сервера моста. Иначе REDSMS ответит 401 и виджет покажет ошибку авторизации.

## 4. Проверить и опубликовать

1. Пройти сквозную проверку из [TESTING.md](TESTING.md#3-сквозная-проверка-в-okocrm).
2. Загрузить новую версию с отметкой «публичный» и отправить на модерацию OkoStore. Требования модерации:
   - понятное описание;
   - код без минификации;
   - в `config.json` нет неиспользуемых `icons`.

После публикации всех клиентов обслуживает один мост. Клиенты различаются по `setting_ulid`, у каждого свой токен.

## Что видит клиент OkoCRM

- Кнопка SMS в карточке клиента, выбор отправителя в шаблонах и в автодействии «Отправить SMS».
- В ленте: одна галка — REDSMS принял сообщение, две галки — доставлено. Если не доставлено, появляется красная заметка с причиной и кнопкой «Повторить».
- Если ключ неверный или кончился баланс, кнопка SMS гаснет, а в настройках виджета виден текст ошибки. Администратору приходит письмо от OkoCRM.
